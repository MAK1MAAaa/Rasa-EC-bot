Safety boundary

真正的风险不在模型答错一句话，而在模型越权写库

禁止路径

用户一句话触发模型直接创建订单、申请售后、取消订单或修改地址。

风险：权限绕过、状态错误、数据污染、现场演示不可恢复。

实际路径

模型只生成待确认草稿；用户确认后，后端重新校验并执行事务。

收益：自然语言入口保留，业务写入边界清晰。

Engineering choices

系统价值来自五个边界清晰的工程选择

Rasa

稳定流程

处理高频、确定、结构化客服任务。

Agent

复杂理解

处理推荐解释、多轮上下文和复杂意图。

API

受控写入

后端统一校验权限、状态和事务。

Data

事实来源

PostgreSQL 为准，Redis 只做缓存和辅助。

第五个选择是 本地化可复现：模型、数据库、图片、benchmark 都可以在本机链路中完成演示和实验。

Engineering choices
Benchmark

LoRA 在推荐扩展上有正向信号，但不是全局增强器

Rasa only 规则稳定

适合固定流程，但不适合承担复杂推荐和多模态任务。

Rasa + LLM 综合主线

规则稳定性与复杂理解能力互补，是当前系统主线方案。

Rasa + LoRA 局部增强

推荐扩展有正向信号，但不能简单宣称全场景提升。

答辩表述：benchmark 用来说明能力边界和方案选择，不把局部实验结果夸大为全局结论。
